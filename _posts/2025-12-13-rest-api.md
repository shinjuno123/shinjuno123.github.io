## Client and Servers
- Client: it can be any devices including the browser or smartphones. It recieves/send the data from/to the server, which has the integrated datasbase. It communicates with server using "API"
- Server: It lives in the internet cloud. It support data processing to DB for input/output operations. It interacts with client.

## What is API?
- A: Application
- P: Programming
- I: Interface
- An API helps clients communicate what they want to the service so it can understand and fulfill the request.

### What is REST?
- REpresentational
- State
- Transfer
- A set of guiding principles that impose conditions on how an API should work.


### What is a REST API?
- A REST or RESTFUL API is one that conforms to the REST architectural style.

### How to identify resources in a REST API?
- A resource is any object, document or thing that the API can receive from or send to clients.
   - e.g. songs, users, posts

```
http://example.com/games (Uniform Resource Identifier, URI)

Protocol
http://

Domain
example.com

Resource
/games
```

### How to interact with a REST API
- POST: Creates new resources
- GET: Retrieves the resource representation/state
- PUT: Updates an existing resource
- PATCH: Update partial attributes of an existing resource 
- DELETE: Deletes a resource

### Data Format
- JSON is the defecto format of the data transfered because it is easy to read and it is all supported by all any major frameworks

### Route format
- GET /games -> get multiple games (200 OK)
- GET /games/1 -> get game that has number 1 as an identifier (200 OK)
- POST /games -> It includes the game to be added in the body as below, 201 CREATED when succeeded
```json
{
    "name": "Street Fighter II"
}
```
- PUT /games/1 -> It is going to replace the number 1 game entity with an updated record as below. (204 No Content)
```json
{
    "name": "Street Fighter II Turbo"
}
```

- DELETE /games/1 -> It is going to delete the number 1 game (204 No content)
